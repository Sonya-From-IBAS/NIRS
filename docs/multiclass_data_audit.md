# Этап 2. Данные для проверки многоклассового детектора

28 ноября 2026 года. В PostgreSQL проверены 248 075 записей из трёх закреплённых версий корпусов и активного MySQL-релиза. Подготовлены 500 ID для разбора, по 100 на каждый основной класс. Из них 50 записей SQLStateGuard заслуживают первоочередной проверки переноса. Для трёх классов — обфускации, повышения привилегий и эксфильтрации — независимый внешний эталон с подтверждённым контекстом пока отсутствует. ## Где возникает риск переобучения

1. **NIRS уже участвовал в обучении.** Объединение обучающих частей пяти сохранённых фолдов исторического прогона охватывает все 32 529 очищенных строк. Этим корпусом можно воспроизвести прежние ошибки. Для оценки переноса новых моделей нужен отдельный набор семейств.
2. **Число строк сценарного корпуса завышает разнообразие.** На 300 наблюдений MySQL приходятся 240 различных текстов SQL, 150 пар «допустимо / нарушение», 100 ссылок производных записей на исходные и 10 авторских семейств. В прежнем разбиении у этих строк семь групп. Более консервативная сверка по исходному тексту после маскирования литералов во всех диалектах оставляет четыре компоненты. Четыре прежние группы соединяются через общую форму запросов в производных примерах PostgreSQL, MSSQL и Oracle. Это ограничение общего исследования с ранее использованными родственными примерами. Для эксперимента исключительно на новых MySQL-семействах группы надо рассчитать заново. [Соответствие прежних и новых групп](../results/multiclass_stage2/summary.json).
3. **Источник выдаёт часть ответа.** Если в каждом источнике всегда выбирать его самый частый класс, на этих же данных верными окажутся 79,75% ответов. Глобальный ответ «SQLi» даёт 75,17%. При правиле по источнику полнота обфускации равна нулю. Только наличие шаблона или простые признаки оформления (перенос строки, конечный разделитель, обратные кавычки) дают те же 75,17%. Это описательная проверка состава. Для оценки переноса нужны метрики по классам на отложенных группах. Особенно важны разрешённое делегирование и разрешённое чтение чувствительных данных в тех же приложениях, с тем же стилем и составом контекста, что и нарушения.

500 ID дают 498 различных SQL и 217 компонент. Один и тот же текст может получить разные эталоны при разных политиках. 30 штатных сценариев попарно сопоставлены с 30 выбранными нарушениями. Квоты заданы по основной метке. У подтверждённых смешанных атак сохранены обе допустимые метки. Для NIRS историческая метка указана в собственном поле, множество подтверждённых ответов осталось пустым.

- **50 SQLStateGuard** — 20 штатных и 30 SQLi, все из WordPress, из 50 разных компонент. По проверенным журналам и ключам не найдены совпадения по ID, точному SQL, группе либо грубой форме с обучением. Ключ группы учитывает известные связи. У приложения общая история с предыдущими экспериментами, а страницы журнала и синтаксические формы могут быть родственными. Для зачёта в перенос нужны проверка происхождения MySQL, разбор исходной единицы и исключение этих групп из нового обучения. Во всём SQLStateGuard первый фильтр прошли 143 штатных записи и 57 330 SQLi. Дисбаланс сохраняется даже после исключений. [Статья авторов, раздел 4.1](https://songli.io/papers/SoCC24CR.pdf).
- **70 Superviz26** — полезны для повторной проверки SQLi. Семейства выбранных запросов встречались при разработке или открытой оценке. В текущих четырёх доменах ни одна запись не прошла все критерии нового внешнего MySQL-примера.
- **290 NIRS и 90 контролируемых сценариев** позволяют проверить соответствие исторических меток нашей задаче и качество контекстной разметки. Во всём списке из 500 у 355 ID обнаружена связь с обучающей частью по самому примеру, у 365 — по компоненте, включая эти 355. Незанятое место во внешней проверке сохраняется до получения подходящих примеров.

## Как сверять карточку

Для первых 25 ID, по пять на класс, выгружены основания непосредственно из закреплённых записей. Карточка содержит версию, источник, исходную метку, доказательство и доступность контекста. У контролируемых сценариев сохранены ID политики и операции, область технических прав доступна по ссылке. У публичных SQLi отмечено происхождение параметров. Результаты моделей при отборе не читались. [25 карточек](../results/multiclass_stage2/evidence_cards.json).

Предлагаемый первый ручной проход — 25 карточек. Для каждого решения сохраняем ID, подтверждённые метки, версию доказательства, кто и когда проверил, что было известно до запроса и какие вопросы остались. Спорные решения и заранее отмеченная доля остальных проходят второй просмотр при включении в эталон. Решения рецензентов следует хранить отдельно от пересоздаваемой выгрузки. Права или бизнес-политику можно восстановить из версии конфигурации приложения. Если политика задаётся специально для эксперимента, получившееся наблюдение получает новый ID и происхождение «контролируемый сценарий».

## Воспроизведение

В корне проекта выполнить `.\.venv\Scripts\python.exe -B src/audit_multiclass_data.py` при доступной локальной PostgreSQL и сохранённых исходных снимках. Скрипт использует версии из отчётов импорта, зафиксированные разбиения, планы завершённых прогонов и локальный архив Superviz26. Для NIRS соответствие исходной строке проверяется по SHA-256. Из таблиц исторических прогнозов читаются только ID. В БД изменений нет. [Код](../src/audit_multiclass_data.py) · [Контрольные суммы выгрузок](../results/multiclass_stage2/checksums.json).

Компонента объединяет совпавшие SQL, лексические шаблоны, прежние группы, связи с родителями и заявленные семейства или кампании в пределах приложения. Грубая форма с замаскированными идентификаторами служит дополнительной проверкой пересечения. Внешнее сходство может возникнуть у разных операций, а смысловая зависимость может пережить смену формы. Состав известной истории включает фолды исторического NIRS, настроенные области этапов 8 и 10, сокращённое обучение и перенос SQLStateGuard, пилот Superviz26, ротацию доменов SQLi, роли релиза и зарегистрированную открытую оценку. Столбцы истории отражают обнаруженные связи хотя бы с одним прогоном. Для конкретной новой модели нужна сверка с её собственными ID обучения.
