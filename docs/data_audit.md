# Аудит данных и выбранные корпуса

Аудит проведён 24–25 ноября 2026 года с согласованным ограничением: полноценный SQL-парсер не устанавливался, синтаксическая и семантическая валидность запросов не подтверждалась. В диагностике используются лексические эвристики. Пользователь согласовал сохранение пяти классов NIRS и подключение отдельного SQLi-корпуса SQLStateGuard. Superviz25 оставлен в реестре без загрузки большого CSV.

## Что сохранено

| Версия | Состав | Основание меток |
|---|---:|---|
| Исходный NIRS, `legacy-nirs-stage1` | 32 530 записей | Исходные пять классов |
| `legacy-cleaned-source-reference-v1` | 32 529 записей | Те же классы; удалена одна запись, пустая после `strip()` |
| `sqlstateguard-sqli-reference-v1` | 161 022 уникальных SQL | Авторская категория normal/attack; бинарная метка SQLi |

Идентификаторы снимков находятся в [cleaned_reference.json](../results/stage4/cleaned_reference.json) и [sqlstateguard_import.json](../results/stage4/sqlstateguard_import.json). Снимки зафиксированы в PostgreSQL; исходные CSV, результаты этапа 1 и восемь исторических запусков не изменены. Пересчёта качества моделей на этом этапе нет.

Для исходного контроля явно используется `load_source_reference()`. Он возвращает прежние пять меток, даже если для записи ещё не установлена проверенная бинарная аннотация. Это позволяет сохранить исходное сравнение и его графики. `load_verified()` возвращает отдельный корпус с бинарными метками и документированным основанием.

Исходный `needs_review` после миграции означает отсутствие нового подтверждённого эталона по контракту. Он не создаёт задание вручную переразметить все 32 тысячи строк и не мешает использовать исходный контроль. Работу по улучшению разметки определяют конкретные диагностические флаги и группы сценариев. Для старых privilege/exfiltration права и политика остаются неизвестными.

## Очистка NIRS

В очищенной версии осталось 19 836 legit, 9 479 sqli, 1 910 obfuscated, 682 privilege и 622 exfiltration. Исключение единственной пустой записи объясняет всё изменение размера.

Точных текстовых дублей нет. Есть 59 групп различий по пробелам по краям, по одному дополнительному вхождению в каждой; противоречий исходных меток внутри них нет. Эти строки сохранены: удаление пробелов может менять смысл SQL, например комментариев. Диагностическое `strip()` не применяется к хранимому тексту.

| Исходный класс | Кандидат полного SQL | Кандидат фрагмента | Кандидат обычного текста | Пусто |
|---|---:|---:|---:|---:|
| legit | 11 714 | 146 | 7 976 | 0 |
| sqli | 1 137 | 7 519 | 823 | 1 |
| obfuscated | 129 | 1 754 | 27 | 0 |
| privilege | 619 | 21 | 42 | 0 |
| exfiltration | 515 | 45 | 62 | 0 |

Это подсказки для разделения исследовательских задач, а не новая разметка типа SQL. Они хранятся отдельно от аннотаций. Наличие `SELECT`, комментария или нечётного числа кавычек не подтверждает корректность запроса и не задаёт класс. Ни фрагменты, ни ошибочные попытки не удаляются автоматически. Исходный NIRS по-прежнему содержит смесь единиц наблюдения и не объявляется новым проверенным корпусом полных запросов.

Лексический шаблон скрывает строковые и числовые литералы и обычные комментарии, сохраняет имена объектов и исполняемые комментарии. Он помогает искать связанные примеры; равенство шаблонов не доказывает семантическую эквивалентность или ошибку разметки. Маркеры кодирования и комментариев остаются диагностикой, а не доказательством обфускации или атаки.

## Редкие классы

Из 682 privilege 659 происходят из прежней LLM-генерации; для exfiltration — 611 из 622. Сведения о роли, разрешениях, операции и политике отсутствуют. Это ограничение эталона, а не утверждение, что все эти метки ошибочны.

Групповой разбор сохранён в [rare_class_review.json](../results/stage4/rare_class_review.json). Найдены конструкции изменения прав и учётных записей, обращения к системным каталогам, привилегированного выполнения, файловых операций, чтения и внешних функций. Группы пересекаются, их количества нельзя суммировать как число различных атак.

Например, чтение `information_schema.tables` может быть штатной инвентаризацией; `GRANT` может выполняться уполномоченным администратором; экспорт может быть частью разрешённого резервного копирования. Для вредоносной метки нужны условия, подтверждающие попытку нарушения. Подозрительная форма запроса и название чувствительной таблицы сами по себе таких условий не задают. Синтаксически спорные строки отмечаются для проверки, без объявления результата парсера.

Решение: сохранить исходные метки в контрольном корпусе и не переносить их автоматически в новый проверенный контекстный эталон. На этапе 5 создать сценарии с известными политиками и сложными штатными альтернативами. Пилот — ранее обсуждённые 120 примеров, 60 вредоносных и 60 штатных; окончательный объём определяется после проверки пилота.

## SQLStateGuard

Загружены 12 статических файлов SQL, README и MIT LICENSE из [закреплённой ревизии](https://github.com/dstsmallbird/SQLStateGuard_Dataset/tree/87c7cc7cbdbf27df9eae095b9800be7e27039ca4). Для каждого файла проверены размер, Git blob SHA-1 и SHA-256. [Авторская статья](https://songli.io/papers/SoCC24CR.pdf) описывает SQL приложений web_app и WordPress и normal/attack-категории. Данные получены на лабораторных приложениях; публичная публикация не делает их производственными журналами инцидентов.

| Приложение | Исходных вхождений | Уникальных SQL | Атак среди уникальных | Штатных среди уникальных |
|---|---:|---:|---:|---:|
| web_app | 149 555 | 92 632 | 67 859 | 24 773 |
| WordPress | 151 073 | 68 390 | 64 792 | 3 598 |
| Всего | 300 628 | 161 022 | 132 651 | 28 371 |

Дедупликация выполняется по точному SQL внутри приложения; все 300 628 вхождений, исходные идентификаторы, категории файлов и кратность сохранены в `occurrences`. Это позволяет позднее отдельно сравнивать уникальные запросы и распределение нагрузки. Их баланс классов существенно различается: исходных атак 146 312, штатных вхождений 154 316. Нельзя подменять одно распределение другим при расчёте метрик.

Пустых/NUL-строк и точных текстов с конфликтующими бинарными метками не обнаружено. Общих точных текстов между двумя приложениями в этом релизе нет. При появлении точного конфликта адаптер оставляет записи и исключает их из проверенного корпуса с неизвестным контекстом; первую попавшуюся метку не выбирает. Разные метки одного маскированного шаблона допустимы и автоматически не исключаются.

Метка 1 следует категории файла атаки, метка 0 — normal. Статус `verified` здесь означает проверку соответствия авторскому протоколу, а не независимую экспертную проверку каждой строки и не доказательство успешной эксплуатации. Попытки с ошибочным SQL также остаются атаками. Роли, права, операция, политика и доверенный диалект остаются неизвестными. MySQL-совместимая нагрузка — характеристика источника. Этот корпус подходит для отдельной SQLi-задачи, но не подтверждает качество выявления повышения привилегий, эксфильтрации или работы с контекстом.

Происхождение, категория атаки и идентификатор приложения служат учёту данных. Они не передаются детектору как признаки ответа. Новые LLM-вызовы и генерация SQL не выполнялись; тексты исследуемых запросов не исполнялись в БД.

## Перекрытия и реестр источников

С NIRS у web_app совпадений не найдено. У WordPress совпадают 345 исходных вхождений по точному тексту и 41 753 по нашему лексическому шаблону. Второе число зависит от алгоритма маскирования; это не 41 753 доказанных текстовых дубля. В ревью использовался другой канонизатор. Эти связи нужно учитывать при разбиениях этапа 6. Случайное разделение строк не делает проверку независимой.

SQLiV3 проверен как зеркало: 29 966 из 30 864 записей с корректной бинарной меткой совпадают с прежней Kaggle-частью после `strip()` — около 97,1%. Это подтверждает общность содержимого, без вывода о направлении заимствования. CSV без заголовка; дополнительные пустые колонки допустимы. Наш счётчик даёт 30 919 сырых записей и 55 записей с нечисловыми метками; счётчики ревью отличаются на одну сырую/отброшенную запись, тогда как размер принятого корпуса совпадает. Причина разницы счётчиков не установлена. Новый независимый тест на этом зеркале не строится.

[Реестр](../results/stage4/source_registry.json) содержит девять кандидатов с версиями, условиями доступа, происхождением и основаниями отбора. Это ограниченный поиск, а не заявление об отсутствии других подходящих данных.

- [Superviz25](https://zenodo.org/records/17086037): известный по ревью внешний контроль; версия и MIT-лицензия проверены по метаданным, CSV объёмом 1 053 264 204 байта не загружен по согласованному решению.
- [SQLShare](https://uwescience.github.io/sqlshare/data_release.html): исследовательская нагрузка без подтверждённых меток угроз; автоматически объявлять её штатной и считать FPR нельзя.
- [Zenodo 20139451](https://zenodo.org/records/20139451): метаданные CC BY 4.0 доступны, единица SQL и независимость состава не установлены, корпус не подключён.
- [DB forensic hybrid](https://huggingface.co/datasets/golfoscar/db-forensic-hybrid): потенциально интересен контекстом, но требуется ручное разрешение доступа; данные не получены, запрос доступа не отправлялся.
- [Superviz26](https://zenodo.org/records/19627322): связанное семейство лабораторных данных; лицензия и независимость не установлены полностью, большие файлы не загружены.
- [Работа о ролевом поведении](https://arxiv.org/html/2508.05690v2): методический источник; версионированный разрешённый пакет данных в рамках поиска не установлен.

SQLStateGuard и Superviz25 уже рассматривались в ревью. Они используются как известные источники разработки и контроля переноса, без заявления о новом слепом тесте. Лицензия исходного Kaggle в API указана как Unknown; это фиксирует неполноту сведений. Новые копии исходных корпусов в Git не публикуются.

Таблица [coverage.csv](../results/stage4/coverage.csv) показывает источник, класс/угрозу, заявленный диалект, контекст и основание метки. Обозначения диалектов старой генерации взяты из происхождения; полноценной проверкой синтаксиса они не являются. Проверенного контекстного покрытия четырёх диалектов пока нет.

## Воспроизведение

Требуются окружение и PostgreSQL из [инструкции хранения](storage.md). Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -B src/source_fetch.py
.\.venv\Scripts\python.exe -B src/public_audit.py
.\.venv\Scripts\python.exe -B src/dataset_audit_pipeline.py --legacy ds_448fd86eb7d9fabc54129e02cb81ed235e4a86d056d6ab08bfa7bd8052872c3f --output results/stage4 --include-sqlstateguard
.\.venv\Scripts\python.exe -B src/verify_data_selection.py
.\.venv\Scripts\python.exe -B src/dataset.py list
```

Первый шаг требует доступа к GitHub; загружаются только статические данные и документация закреплённой версии. Повторный импорт переиспользует источники и снимки, а также восстанавливает недостающие регистрации файлов. Аудит зеркала SQLiV3 сохранён отдельно в `sqliv3_overlap.json` с закреплённой ревизией и SHA-256; основной импорт его не выполняет.

Экспорт: `src/dataset.py export-reference <dataset_version_id> <новый-файл.csv>` для пяти классов или `export-verified` для бинарного корпуса. Экспорт поверх исходных `dataset.csv`/`generated.csv` запрещён. Старые функции сборки оставлены для исторической совместимости; основной CLI работает с БД.

Проверки: 47 тестов прошли, включая интеграционные проверки PostgreSQL. Полное сравнение 300 628 импортированных вхождений с сырыми файлами сохранено в `roundtrip_validation.json`. Сохранены SQL, пробелы по краям, исходные категории и порядок. Парсерная проверка не выполнялась: установка SQLGlot не была разрешена. Запоминание имён объектов этим аудитом не исправляется; групповые разбиения и новые признаки предусмотрены этапами 6–7.
