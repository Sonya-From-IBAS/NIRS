# Воспроизведение предварительных результатов

Результаты рассчитаны на этом Windows-компьютере в существующем `.venv`; зависимости закреплены в `requirements-lock.txt`.
Ключи API и параметры доступа PostgreSQL находятся в игнорируемых `.env` и `.env.db.local`, в Git они не входят.

## Пересчёт из сохранённых прогнозов

```powershell
.\.venv\Scripts\python.exe -B src/evaluate.py --manifest results/preview/run_manifest.json
.\.venv\Scripts\python.exe -B src/compare.py --manifest results/preview/run_manifest.json
.\.venv\Scripts\python.exe -B src/replay_preview.py
```

Новых сетевых обращений нет. Replay сверяет кэш ответов по реальным ID наблюдений, заново строит JSON, CSV,
Markdown и все PNG/SVG, затем сравнивает их SHA-256. Политика отказов и неопределённость описаны в `report.md`.

## Подготовка данных и повтор локальных ML-профилей

Базовый путь подготовки: `src/init_storage.py`, Docker Compose из `compose.yaml`, `src/manage_storage.py migrate`,
аудит/импорт публичных источников из `docs/data_audit.md`, `src/import_scenarios.py` и `src/prepare_splits.py`.
После подготовленных снимков и разбиений:

```powershell
.\.venv\Scripts\python.exe -B src/stage10_training.py --prepare-only
.\.venv\Scripts\python.exe -B src/preview_ml.py
```

`--prepare-only` создаёт объединённое разбиение без большого перебора. Фиксированный предварительный профиль
обучается на подмножестве train; validation/test и пороги не переставляются по результатам оценки.
Архивные модели этапа 1 нужны для исторического контроля и уже зарегистрированы в текущей БД.

Результаты LLM зависят от ранее полученных ответов GPT-OSS и закреплённого API-кэша. На новой БД без этого
кэша повтор API-эксперимента требует отдельного расчёта объёма; нельзя считать его бесплатным offline replay.
Для переноса существующих экспериментов предусмотрены `manage_storage.py backup` и `restore-check`.

## Полный профиль

Этап 13 выполняется отдельно. Сохранённые корректные веса, матрицы и API-ответы остаются пригодными к
продолжению; промежуточные предварительные таблицы не заменяют результаты полного профиля. Перед новым
полным прогоном пересчитывается остаток API-бюджета. После него все показатели и графики строятся заново
из новой версии зарегистрированных запусков. Просмотренный предварительный срез не является новым слепым тестом.
